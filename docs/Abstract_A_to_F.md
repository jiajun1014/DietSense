# DietSense — A to F 六段式摘要（完整版）

> 依據 Perplexity 深度研究補充最新數據與引用來源

---

## A. Attention Getter

全球肥胖與過重人口持續攀升，2024 年全球已有 26 億名成人過重，其中 9.4 億人屬肥胖；肥胖已成為需要長期管理的慢性公共衛生問題。 然而，飲食記錄雖有助於體重管理，傳統 App 仍要求使用者手動搜尋食物、秤重、選擇份量並拆解複合菜餚，認知負擔高且難以持續。對臺灣民眾而言，「一碗加蛋牛肉麵、半碗湯、一份滷味」究竟含多少熱量與營養，往往難以即時、可信地回答。DietSense 旨在將被動、繁瑣的熱量記錄，轉化為以自然語言驅動、具臺灣在地飲食理解與安全守門的個人化體重管理 AI Agent。[[who](https://www.who.int/news-room/fact-sheets/detail/obesity-and-overweight)][[pubmed.ncbi.nlm.nih](https://pubmed.ncbi.nlm.nih.gov/41081011/)][[pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC13029413/)]

## B. But：挑戰

現有飲食追蹤工具存在三大瓶頸。第一，手動記錄負擔高：使用者必須搜尋食物、選擇品牌與份量、拆解複合料理，導致記錄中斷與長期留存率低；SMARTER 12 個月試驗亦顯示，飲食自我監測的遵循率會隨時間非線性下降，且基線 BMI 較高者遵循率更低。 第二，自報飲食攝取誤差可達 18%–54%，份量模糊、隱藏油脂、湯底與混合料理進一步擴大熱量與巨量營養素估計的不確定性。 第三，通用 LLM 雖能理解自然語言，但直接詢問「這餐有多少熱量」容易產生幻覺、虛構數值或提供未經驗證的營養建議；研究顯示，LLM 對食物影像的熱量估計 MAPE 約為 35.8%，重量估計 MAPE 約 36.3%，且對大份量常有系統性低估。[[pubmed.ncbi.nlm.nih](https://pubmed.ncbi.nlm.nih.gov/41081011/)][[frontiersin](https://www.frontiersin.org/articles/10.3389/fnut.2025.1635682/full)]

## C. Cure：解藥

本研究提出 DietSense，一個對話式、資料錨定且安全導向的 Domain AI Agent，而非單純問答 Chatbot。使用者能以日常中文描述飲食，例如「我剛吃了一碗加蛋台式牛肉麵，湯喝一半」；系統透過 LLM 理解意圖、辨識食物實體、主動追問模糊資訊，並呼叫可稽核工具完成營養檢索、熱量計算與個人化分析。

其核心設計是「LLM 負責協調，領域工具負責計算」：LLM 不直接生成熱量或醫療建議，而是透過白名單 Function Calling 呼叫營養資料庫、RAG 檢索、Mifflin-St Jeor TDEE 引擎、不確定性量化模組與安全規則庫。如此可將 USDA FoodData Central、臺灣食品成分資料庫與自建臺式料理向量資料庫作為事實來源，降低幻覺風險，並以熱量區間、信心分數與來源揭露取代虛假精確的單一數字。[[pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC13029413/)]

## D. Development：方法

DietSense 採八模組架構：使用者輸入、語音轉文字與意圖分類、Planner 推理、資料檢索、分析引擎、領域知識整合、決策建議及輸出互動。 系統以 Whisper 將語音轉為文字，經繁簡正規化與意圖分類後，由 LLM Planner 判斷任務類型，包括記錄飲食、查詢營養、分析攝取或提出建議；當食物、份量或烹調方式模糊時，觸發 Clarification Loop 主動追問。

資料層整合 USDA FoodData Central、臺灣食品成分資料庫、向量 RAG 與使用者歷史飲食紀錄；分析層以 E = portion(g) × kcal\_per\_100g / 100 計算熱量，並結合 Mifflin-St Jeor 公式估算 BMR 與 TDEE，進一步產生巨量營養素比例、攝取缺口與替代建議。 系統亦導入不確定性傳遞：當信心度低於門檻時，要求使用者澄清；當資料不足時，輸出信賴區間而非假精確值。安全層則設定每日熱量低於 1,200 kcal、極端節食語句與飲食失調風險的攔截機制，並對孕婦、慢性病與用藥族群導向專業人員。[[frontiersin](https://www.frontiersin.org/articles/10.3389/fnut.2025.1635682/full)]

## E. Experiments：評估

本研究將建立 500 筆臺式料理與外食描述標註資料集，涵蓋夜市小吃、便當、湯麵、複合料理、飲料與常見家庭菜餚，並結合 USDA 與臺灣食品成分資料庫進行混合測試。 評估將比較 DietSense 與 MyFitnessPal 手動輸入流程，並以熱量絕對誤差、±10% 與 ±20% 誤差內達標率、巨量營養素誤差、涵蓋率、記錄時間與安全攔截率作為主要指標。

使用者研究將招募 20 名參與者，進行 7 天真實飲食記錄，比較自然語言輸入與傳統手動輸入的完成時間、中斷率、主觀負擔與系統可用性；可用性將以 System Usability Scale（SUS）評估，目標為高於 70 分。 為避免虛構結果，提案階段僅陳述預期成效：預期在 ±20% 熱量誤差內達成高於 85% 的準確率、記錄時間縮短約 60%，並維持高來源揭露率與安全降級率；所有數值將於實作後以實測結果驗證。[[pubmed.ncbi.nlm.nih](https://pubmed.ncbi.nlm.nih.gov/41081011/)][[pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC13029413/)]

## F. Findings：預期產出

預期 DietSense 能將傳統「被動式熱量追蹤」轉化為「主動式、情境感知的個人化體重管理」。系統預期輸出包含熱量與巨量營養素區間、個人化 TDEE 差距、飲食替代建議、趨勢圖與可解釋的資料來源，而非僅提供單一熱量數字。

其學術貢獻在於整合四項要素：可運作的繁體中文飲食 Agent、500 筆臺式料理標註資料集、多來源營養整合管線，以及兼顧準確度、可用性與安全性的多維評估框架。 更重要的是，DietSense 將 LLM 的角色限制為理解、協調與互動，將營養計算、資料檢索與安全判斷交由可稽核工具完成；此設計可降低幻覺風險，並使 AI 建議在真實飲食情境中更具可信度與可部署性。[[pubmed.ncbi.nlm.nih](https://pubmed.ncbi.nlm.nih.gov/41081011/)][[frontiersin](https://www.frontiersin.org/articles/10.3389/fnut.2025.1635682/full)]

---

### 預期貢獻與學術價值

1. **可運作的繁體中文對話式飲食 Agent 原型**：結合 LLM Function Calling、台灣食品資料庫、Mifflin-St Jeor TDEE 計算引擎的完整端到端系統
2. **500 筆臺式料理標註資料集**：涵蓋夜市小吃、便當、複合料理、手搖飲等，填補現有西方資料庫的台灣食物缺口
3. **不確定性誠實量化機制**：輸出熱量區間（低~高），基於信心分數動態調整，避免偽精確單一數字
4. **多維評估框架**：同時評估準確度（±20%）、可用性（SUS）、安全性（攔截率）與來源揭露率
5. **安全守門設計**：偵測飲食失調風險，拒絕危險限制建議，導向專業營養師
